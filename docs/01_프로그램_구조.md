# 프로그램 구조 설명 (초보자용)

> 이 문서는 코드를 처음 보는 분을 위해 썼습니다. 용어가 낯설면 맨 아래 **용어 사전**을 먼저 보세요.

---

## 1. 한 줄 요약

**파워포인트 보고서를 읽어서, 특허로 낼 만한 문장에 형광펜을 칠하고(= 출원검토필요 표시) 첫 슬라이드에 색상 범례를 붙여 돌려주는 프로그램**입니다.
인공지능(LLM)을 쓰지만 **내 컴퓨터 안에서만** 돌아가고, 인터넷으로 아무것도 보내지 않습니다.

---

## 2. 등장인물은 셋입니다

```
 ┌──────────────┐   파일 업로드    ┌──────────────────┐   "이 문장 특허감이야?"   ┌──────────────┐
 │  ① 브라우저   │ ──────────────▶ │  ② 우리 프로그램   │ ───────────────────────▶ │  ③ Ollama    │
 │  (화면)      │ ◀────────────── │  (파이썬 서버)     │ ◀─────────────────────── │  (AI 실행기)  │
 └──────────────┘  마킹된 PPTX     └──────────────────┘      JSON 답변              └──────────────┘
   index.html          app/ 폴더의 파이썬 파일들                 qwen3:8b 모델을 메모리에 올려 둠
```

| 등장인물 | 정체 | 이 프로젝트에서의 위치 |
|---|---|---|
| ① 브라우저 | 사용자가 보는 화면. 파일을 올리고 결과를 봅니다. | `app/static/index.html` |
| ② 우리 프로그램 | 파일을 읽고, 후보를 찾고, PPTX 에 마킹합니다. | `app/*.py` |
| ③ Ollama | AI 모델을 내 컴퓨터에서 실행해 주는 **별도 프로그램**. 우리가 만든 게 아니라 설치하는 것입니다. | 설치형 (setup 스크립트가 깔아 줌) |

②와 ③은 같은 컴퓨터 안에서 `127.0.0.1`(= "나 자신") 주소로만 대화합니다. 그래서 외부로 데이터가 나가지 않습니다.

## 3. 파일 하나가 처리되는 흐름 (5단계)

```
  보고서.pptx
      │
      ▼
 [1] extract.py  ─ PPTX 를 열어 글자를 전부 꺼낸다. 문단 하나 = Segment 하나.
      │              (본문, 표, 차트 제목, 발표자 노트까지)
      ▼
 [2] lexicon.py  ─ 규칙 사전(정규식)으로 "수상한 문단" 을 넓게 찾는다.
      │              예) "자체 개발", "40% 절감", "22~28°", "전시 시연"
      ▼
 [3] analyze.py  ─ 슬라이드 한 장씩 Ollama(Qwen3)에게 보내 판정을 받는다.
      │              "어느 구간이, 왜, A/B/C 중 무엇인가" 를 JSON 으로 받음
      ▼
 [4] merge.py    ─ [2]와 [3]의 결과를 합친다.
      │              · 모델 답의 인용구를 원문의 정확한 글자 위치로 바꿈
      │              · 매출·이익률 같은 경영 숫자 오탐은 등급을 내림
      │              · 모델이 놓쳤지만 사전 점수가 높은 문단은 구제(안전망)
      ▼
 [5] mark.py     ─ PPTX 에 그려 넣는다.
      │              · 형광펜 + 밑줄          · 첫 슬라이드 색상 범례 상자
      │              · 슬라이드 배지          · 발표자 노트 주석 + 요약 슬라이드
      │              · (선택) 【출원검토필요】 문구 — 흑백 인쇄용, 기본은 끔
      ▼
  보고서_특허마킹.pptx
```

`main.py` 가 이 다섯 단계를 순서대로 부르는 "지휘자" 이고, `config.py` 는 모두가 참고하는 "설정 메모장" 입니다.

### 예시로 따라가기

슬라이드 4에 이런 문장이 있다고 합시다.

> 조명 입사각을 22~28° 구간에서 가변한 결과 미세 크랙 대비비가 최대. 24°를 표준 사양으로 확정하고 각도 가변 마운트를 자체 제작.

| 단계 | 일어나는 일 |
|---|---|
| [1] extract | 이 문장이 `Segment(seg_id=57, slide_no=4, text="조명 입사각을 …")` 가 됨 |
| [2] lexicon | `22~28°` → 수치·범위한정, `표준 사양으로 확정` → 최적화·조건확립, `자체 제작` → 독자성주장 이 걸림 |
| [3] analyze | 모델이 `{"seg_id":57, "quote":"22~28° 구간", "grade":"A", ...}` 와 `{"quote":"자체 제작", "grade":"B", "implicit":true, ...}` 를 돌려줌 |
| [4] merge | `"22~28° 구간"` 이 원문의 8~14번째 글자임을 확정. 두 건 모두 유지 |
| [5] mark | 8~14번째 글자에 노란 형광펜, `자체 제작` 에 하늘색 형광펜, 슬라이드 오른쪽 위에 `출원검토필요 2건` 배지, 첫 슬라이드에 색상 범례 상자 |

## 5. 파일별 상세

### `app/config.py` ─ 설정 메모장
- **하는 일**: 모델 이름, 주소, 색상, `출원검토필요` 표현(배지·범례·문구) 같은 값을 한곳에 모아 둠.
- **바꿀 만한 곳**: `MODEL`(모델 교체), `GRADE_COLOR`(형광펜 색), `BADGE_TEXT`·`LEGEND_TITLE`(표현), `SLIDE_BADGE`·`SLIDE_LEGEND`(배지·범례 끄기).
- 코드 로직이 없어서 가장 안전하게 건드릴 수 있는 파일입니다.

### `app/extract.py` ─ [1] 읽기
- **하는 일**: PPTX 안의 글자를 전부 꺼내 `Segment` 목록으로 만듦.
- **핵심 함수**: `extract(path)` → `Deck`
- **알아 둘 것**: 각 `Segment` 는 글자뿐 아니라 "원래 자리(XML 문단)" 참조를 들고 있어서, 마킹 단계에서 그 자리로 돌아갈 수 있습니다.

### `app/lexicon.py` ─ [2] 규칙 사전
- **하는 일**: 30여 개 정규식 규칙으로 특허 단서 표현을 찾음. 카테고리와 가중치를 붙임.
- **핵심 함수**: `scan(text)` → `Hit` 목록, `score()`, `is_business_noise()`
- **바꿀 만한 곳**: `RULES` (규칙 추가·수정), `NOISE` (경영 용어 추가). **업종이 바뀌면 가장 먼저 손볼 파일.**

### `app/analyze.py` ─ [3] 모델 판정
- **하는 일**: 슬라이드 한 장의 문단을 Ollama 에 보내고 JSON 답을 `Finding` 목록으로 바꿈.
- **핵심**: `SYSTEM` (모델에게 주는 업무 지시서), `SCHEMA` (답의 형식 강제), `_analyze_batch()` (실제 호출)
- **바꿀 만한 곳**: 판정 기준을 바꾸고 싶으면 `SYSTEM` 프롬프트.

### `app/merge.py` ─ [4] 병합
- **하는 일**: 모델 답의 인용구를 글자 위치로 변환, 오탐 강등, 누락 구제, 겹치는 구간 병합.
- **핵심 함수**: `resolve()` → (최종 `Finding` 목록, `Mark` 목록)
- **바꿀 만한 곳**: `RESCUE_SCORE` (안전망 민감도).

### `app/mark.py` ─ [5] 쓰기
- **하는 일**: PPTX XML 을 직접 편집해 형광펜·문구·배지·노트·요약 슬라이드를 넣음.
- **핵심 함수**: `apply()` (진입점), `highlight()` (문단 하나 칠하기), `_split_run()` (글자 덩어리 쪼개기)
- **알아 둘 것**: PowerPoint 는 XML 요소 순서에 민감합니다. `_insert_ordered()` 가 그 순서를 지킵니다.

### `app/evaluate.py` ─ [7] 성능 측정
- **하는 일**: 검토 반영으로 쌓인 확정 정답을 문제지 삼아, 최초 설정(기본 사전·기본 프롬프트·qwen3:8b)과
  현재 설정(사전 추가·예시 주입)을 같은 문제로 채점해 재현율·정밀도·F1 을 계산. 회차별 이력 누적.
- **핵심 함수**: `build_eval_set()` (문제지 만들기), `run_sync()` (한 회차 실행), `history()`
- **알아 둘 것**: 이력은 `review_data/eval_history.jsonl` 에 쌓입니다. 사용법은 [04_성능_측정.md](04_성능_측정.md).

### `app/main.py` ─ 지휘자 (웹 서버)
- **하는 일**: 브라우저 요청을 받아 [1]~[5] 를 순서대로 실행. 진행 상황을 브라우저에 알려 줌.
- **핵심 함수**: `_run()` (파이프라인), `create_job()` (업로드 받기), `serve()` (서버 시작)

### `app/static/index.html` ─ 화면
- **하는 일**: 파일 올리기, 옵션 체크박스, 진행률, 결과 목록, 내려받기 버튼.
- CSS/JS 가 전부 이 파일 안에 있어 인터넷 없이도 열립니다.

## 6. 코드를 읽는 추천 순서

1. `config.py` ─ 어떤 설정이 있는지 훑기 (5분)
2. `main.py` 의 `_run()` ─ 전체 흐름 파악 (10분)
3. `extract.py` ─ 데이터가 어떤 모양(`Segment`)인지 (10분)
4. `lexicon.py` 의 `RULES` 몇 개 ─ 규칙이 어떻게 생겼는지 (10분)
5. `analyze.py` 의 `SYSTEM` ─ 모델에게 뭘 시키는지 (10분)
6. `merge.py` → `mark.py` ─ 결과가 어떻게 파일에 들어가는지 (30분)

## 7. 자주 하는 수정 레시피

| 하고 싶은 것 | 어디를 | 어떻게 |
|---|---|---|
| `출원검토필요` 표현 바꾸기 | `config.py` | `BADGE_TEXT`(배지), `LEGEND_TITLE`(범례 제목), `TAG_TEXT`(선택 문구) |
| 흑백 인쇄용으로 구간마다 문구도 붙이기 | 화면 | `문구도 표시` 체크 (형광펜 구간 뒤에 `【출원검토필요】` 가 들어감) |
| 배지·범례 끄기 | `config.py` | `SLIDE_BADGE = False`, `SLIDE_LEGEND = False` |
| 형광펜 색 바꾸기 | `config.py` | `GRADE_COLOR["A"] = "FFFF00"` (6자리 RGB, `#` 없이) |
| 모델 바꾸기 (나중에 업그레이드) | `config.py` | `MODEL = "모델명"` (`ollama pull 모델명` 으로 먼저 받기) |
| 새 단서 표현 추가 | `lexicon.py` | `RULES` 에 `_r("이름", "카테고리", 가중치, r"정규식", "설명"),` 한 줄 추가 — 정규식 없이 하려면 웹 화면 [검토 반영] 탭의 [사전에 추가] 버튼 |
| 검토완료본으로 판정 개선 | 웹 화면 [검토 반영] 탭 | 사용법은 [03_검토반영_사용법.md](03_검토반영_사용법.md) |
| 개선 폭을 숫자로 재기 | 웹 화면 [성능 기록] 탭 | 사용법은 [04_성능_측정.md](04_성능_측정.md) |
| 경영 용어 오탐 줄이기 | `lexicon.py` | `NOISE` 정규식에 단어 추가 |
| 판정 기준 바꾸기 | `analyze.py` | `SYSTEM` 문자열 수정 |
| 안전망 민감도 | `merge.py` | `RESCUE_SCORE` (낮추면 더 많이 구제) |
| 화면 문구·색 | `index.html` | 위쪽 `<style>`(색), 중간 `<body>`(문구) |

수정 후에는 `python tests/smoke.py` 를 한 번 돌려 파일이 정상 생성되는지 확인하세요.

## 8. 용어 사전

| 용어 | 뜻 |
|---|---|
| **LLM** | 대규모 언어 모델. ChatGPT 같은 AI. 여기서는 Qwen3 라는 공개 모델을 씀 |
| **온디바이스 / 오프라인** | 서버(클라우드)가 아니라 내 컴퓨터에서 실행한다는 뜻 |
| **Ollama** | LLM 을 내 컴퓨터에서 쉽게 실행해 주는 프로그램. `ollama serve` 로 켜고, `ollama pull 모델명` 으로 모델을 내려받음 |
| **Qwen3:8b** | 알리바바가 공개한 LLM. 8b = 파라미터 80억 개. 파일 크기 약 5GB |
| **토큰** | 모델이 글을 다루는 최소 단위. 한글 한 글자 ≒ 1토큰 |
| **Python / 파이썬** | 이 프로그램이 쓰인 언어 |
| **가상환경 (.venv)** | 이 프로젝트 전용 파이썬 라이브러리 보관함. 다른 프로그램과 섞이지 않게 함 |
| **라이브러리 / 패키지** | 남이 만들어 둔 코드 묶음. `requirements.txt` 에 목록이 있음 |
| **pip** | 파이썬 라이브러리 설치 도구 |
| **FastAPI / uvicorn** | 파이썬으로 웹 서버를 만드는 라이브러리 / 그것을 실행하는 프로그램 |
| **python-pptx / lxml** | PPTX 파일을 읽고 쓰는 라이브러리 / XML 을 다루는 라이브러리 |
| **정규식 (regex)** | "글자 패턴" 을 적는 약속. `lexicon.py` 의 규칙이 이것 |
| **JSON** | `{"이름": "값"}` 모양의 데이터 형식. 모델 답과 브라우저 통신에 쓰임 |
| **127.0.0.1 / localhost** | "내 컴퓨터 자신" 을 뜻하는 주소 |
| **포트** | 한 컴퓨터 안에서 프로그램을 구분하는 번호. 우리 서버 8765, Ollama 11434 |
| **Segment** | 문단 하나를 담는 상자 (`extract.py`) |
| **Finding** | 판정 결과 하나 (`analyze.py`) |
| **Mark** | 실제로 칠할 구간 하나 (`merge.py`) |
| **등급 A/B/C** | A 즉시 출원 검토 · B 발명 발굴 필요 · C 참고 |
| **묵시적 표현** | 기술 수단이 안 적혀 있지만 "있어야만 하는" 표현. 예: "40% 절감", "자체 개발" |
| **공개 리스크** | 전시·논문·납품 등으로 이미 외부에 드러난 내용. 특허 신규성에 문제될 수 있음 |
| **런 (run)** | PPTX 안에서 서식이 같은 글자 덩어리. `<a:r>` |
